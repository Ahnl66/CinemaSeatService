## Authorized DTS-HD MA source

The explicitly supplied local Matroska source has DTS-HD MA 5.1(side), 48 kHz,
16-bit audio, not the untested 7.1/24-bit target case. The bounded host extractor
selects its audio only. The reference decoder uses the full HD profile, not DTS core.

Running 0.1.1 rejects its side layout as unsupported_format. Local 0.1.2 preserves
that layout and reaches the next guard: timeline_discontinuity. At decoded frame
11, container PTS 116 ms corresponds to 5568 samples, while counting valid samples
from the first anchor expects 5632. Difference: 64 samples (1.333 ms). The approved
maximum for its 1/1000 time base is 48 samples (one millisecond).

The strict guard is preserved. The first 12 observed timestamp values have become
a synthetic, media-free regression that must reject this discrepancy. No tolerance
increase, timestamp rebias or missing-PTS substitution is used to mark the source
playable. Reference codec success and source-timeline acceptance remain separate.

A fresh native arm64 image was built on the ODROID without replacing the existing
Dockge stack. Runtime image:
`sha256:bd40bf86a8d97910daa8df272e11c6195798cf12599fa93a3478deb1a07adc68`.
Build ID: `1fa9b2358dc7788f45d8f4f6da173cb92e717050fea78bf1dc989210c14ce462`.
The test container used a read-only root, non-root user, dropped capabilities,
512 MiB limit, settings-only mount and a localhost-only port through a temporary
SSH tunnel. It is removed after testing; the built candidate image is retained.

The candidate passed 8 single-session, 16 two-session and 32 four-session exact
PCM checks, now including DTS 5.1(side). All session slots recovered. During a
35-second withheld-output-credit test, two pings were answered, the producer was
observed waiting for input credit and cancellation completed in about 7.4 ms.
Received audio stayed within the initial output budget; no new output credit was
granted. This is a bounded backpressure test, not a one-hour endurance result.

The original authorized source is still rejected with timeline_discontinuity.
Partial evidence is retained across teardown: one FLAC packet, 4096 valid samples,
48 kHz/16-bit, explicit FL/FR/FC/LFE/SL/SR, source_profile dts-hd-ma. No end_output
was received, so no complete source roundtrip is claimed.

Additional host evidence groups packets by demux position. The five-second
fixture contains 61 groups of 3–8 packets; their actual block anchors deviate
only -16 through +16 samples. Derived timestamps inside groups deviate up to
80 samples. The pinned Matroska demuxer distributes an integer block duration
among laces (`matroskadec.c`, around lines 4367–4418), consistent with the observed
double-quantization pattern. This identifies a focused demux/reliability issue;
it does not authorize silently retiming packets or relaxing the protocol guard.
A future correction must first be source-gated in existing Diagnose, with raw
versus derived timestamp evidence and unchanged physical acceptance requirements.

## Second authorized DTS-HD MA source

The second authorized source was inspected with the existing host-only extractor
and pinned strict decoder. Initial container probing reported a six-channel hint.
The reference decoder then requested XLL recovery on its first packet; the strict
patch rejected it before a full lossless frame. The normal check failed preflight
with `source_reference_decode_failed`; no audio session was sent to the service.

A separate bounded metadata-only continuation rejected that one packet and
inspected eight subsequent noncorrupt full-HD frames. These report DTS-HD MA,
48 kHz, 24-bit and eight speakers: FL/FR/FC/LFE/BL/BR/SL/SR. Thus this source
provides the requested 7.1/24-bit material, but is not accepted for playback.
Leading coverage is missing and no complete PCM equivalence or source timing pass
is claimed. The runtime recovery policy is unchanged. No silent core fallback,
lossy recovery or first-packet trimming is enabled. A real TrueHD 7.1 source is
still missing. See the portable [source evidence](DTSHD_7_1_2026-11-01.json).
